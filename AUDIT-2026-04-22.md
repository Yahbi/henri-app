### CRITICAL — Live/demo scoring uses wrong component ranges

**File:** `src/lib/permits/live.ts`, lines 50–54

The live scoring model uses a completely different 4-component system than the documented 6-component model:

| Component | Live model max | Real model max |
|-----------|---------------|----------------|
| freshness | **25** | 20 |
| value | **25** | 20 |
| contact | 15 | 15 |
| demand | **25** | 15 |
| engagement | **0 (hardcoded)** | 15 |
| conversion | **0 (hardcoded)** | 15 |
| **Theoretical max** | **90** | **100** |

Impact: When `ScoreSignalBreakdown.tsx` renders a live lead with `score_freshness: 25`, it displays "25/20" — a bar at 125% width (visually clamped by CSS `overflow-hidden`, but the numeric label shows a value exceeding the documented maximum). Contractors see impossible numbers.

**Fix:** Align the live model to the real model's ranges (max 20/20/15/15 per component), or add a proportional scaler. Most correct fix:

```diff
// src/lib/permits/live.ts, lines 50-54

+ const freshnessScore = Math.min(20, Math.round(20 * (1 - Math.min(daysOld, 90) / 90)));
+ const valueScore = Math.min(20, Math.round((Math.min(p.estimated_value ?? 0, 200_000) / 200_000) * 20));
  const contactScore = (p.owner_first || p.owner_last) ? 15 : 8;
- const demandScore = Math.min(25, 10 + (hashCode(p.address ?? `p${index}`) % 16));
```

### CRITICAL — "avg" label on what is actually a sum

**File:** `src/app/(dashboard)/dashboard/roi/page.tsx`, line 313

`cat.totalValue` is a **sum** of all permit values in that category (populated in `src/app/api/intelligence/route.ts` line 87: `entry.totalValue += p.estimated_value ?? 0`). **Fix:**
```diff
- ${(cat.totalValue / 1000).toFixed(0)}K avg
+ ${(cat.count > 0 ? (cat.totalValue / cat.count / 1000).toFixed(0) : 0)}K avg
```

### MEDIUM — Capacity filter hides null-value leads asymmetrically

**File:** `src/lib/capacity/types.ts`, lines 108–109

```typescript
if (prefs.value_min != null && (lead.rawValue ?? 0) < prefs.value_min) return false;
if (prefs.value_max != null && (lead.rawValue ?? Infinity) > prefs.value_max) return false;
```

Leads with unknown permit values (`rawValue = null`) are treated as $0 for min-check and Infinity for max-check. Setting any value range filter hides all leads without value data — silently. This contradicts the wedge rule: *"Never silently drop rows."*

**Fix:** Exclude null-value leads from value filtering (let them through):
```diff
- if (prefs.value_min != null && (lead.rawValue ?? 0) < prefs.value_min) return false;
- if (prefs.value_max != null && (lead.rawValue ?? Infinity) > prefs.value_max) return false;
+ if (prefs.value_min != null && lead.rawValue != null && lead.rawValue < prefs.value_min) return false;
+ if (prefs.value_max != null && lead.rawValue != null && lead.rawValue > prefs.value_max) return false;
```

### Score breakdown bar threshold inconsistency

**File:** `src/components/dashboard/ScoreSignalBreakdown.tsx`, line 57

```typescript
pct >= 75 ? "bg-hot" : pct >= 45 ? "bg-warm" : pct > 0 ? "bg-cool" : "bg-border"
```

The warm-bar threshold is `>= 45%` instead of `>= 50%`. Every other urgency boundary in the app uses 50 as the warm/cool cutoff. This creates visual inconsistency — a signal at 47% shows warm (gold) in the breakdown but would be "cool" (blue) by the lead's overall score convention.

**Fix:**
```diff
- pct >= 75 ? "bg-hot" : pct >= 45 ? "bg-warm" : pct > 0 ? "bg-cool" : "bg-border"
+ pct >= 75 ? "bg-hot" : pct >= 50 ? "bg-warm" : pct > 0 ? "bg-cool" : "bg-border"
```

### ScoreBreakdown.tsx hides zero-value signals

**File:** `src/components/dashboard/ScoreBreakdown.tsx`, lines 51–56

When engagement or conversion scores are 0, the entire bar is hidden (`engagement > 0 && ...`). Combined with the live scoring issue (engagement and conversion are always 0 for demo leads), these signals are permanently invisible in demo mode. For real leads that genuinely score 0, hiding the bar confuses contractors into thinking the signal doesn't exist rather than understanding it scored zero.

**Fix:** Always render all 6 signals; show an empty bar with "0/15" for zero-score components.

### Duplicated formatCompact implementations

Six separate implementations of the same K/M money-formatting logic exist across the codebase with minor behavioral differences:

1. `src/lib/scoring/model.ts` (private)
2. `src/lib/capacity/types.ts` (private `fmt`)
3. `src/lib/outreach/tokens.ts`
4. `src/components/dashboard/PermitHistorySection.tsx` (line 41)
5. `src/components/dashboard/LeadsPanel.tsx` (line 44)
6. `src/app/api/cron/weekly-digest/route.ts`

Some use `.toFixed(1)` for M values but `Math.round` for K; the weekly-digest version uses `.toFixed(1)` for K too, producing "$12.0K" while the dashboard shows "$12K".

**Fix:** Consolidate into a single `formatCompactCurrency()` in `src/lib/utils/format.ts` and import everywhere.
